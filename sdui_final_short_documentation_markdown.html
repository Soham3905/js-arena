Server-Driven UI (SDUI) Documentation

Introduction

Server-Driven UI (SDUI) is a modern frontend architecture where the server controls the UI structure and the frontend dynamically renders the UI based on the data received from the backend.

Instead of hardcoding every screen inside the frontend, the backend sends UI configuration in JSON format.

This helps applications update UI quickly without requiring frequent app updates.

What is SDUI?

SDUI stands for Server-Driven UI.

In SDUI:

  • Backend decides what to show

  • Frontend decides how to render it

The server sends:

  • layout

  • themes

  • components

  • actions

  • configurations

The frontend reads this data and dynamically renders the UI.

Why SDUI Was Introduced

Traditional frontend systems had several problems:

  • Small UI changes required app updates

  • Frequent deployments were needed

  • Dynamic layouts were difficult

  • A/B testing was hard

  • Multiple platforms required separate UI logic

Companies needed:

  • faster UI updates

  • personalization

  • dynamic layouts

  • remote UI control

  • reusable components

SDUI solves these problems.

Traditional UI vs SDUI

Traditional UI

Frontend Code → Build App → Deploy → User Updates App

UI is fixed inside frontend code.

SDUI

Frontend Requests Config

        ↓

Server Sends JSON

        ↓

Frontend Dynamically Renders UI

UI becomes flexible and dynamic.

Basic SDUI Example

Backend JSON

{

  "type": "hero",

  "title": "Welcome to SDUI"

}

Frontend Renderer

if(component.type === "hero") {

   return <Hero title={component.title} />

}

The frontend renders components dynamically using backend data.

SDUI Architecture

Main Parts

1. Backend Server

Responsible for:

  • sending UI config

  • themes

  • layouts

  • business logic

2. Renderer Engine

Frontend system that:

  • reads JSON

  • maps components

  • renders UI dynamically

3. Component Registry

Maps JSON types to frontend components.

Example:

{

  hero: HeroComponent,

  footer: FooterComponent

}

4. Reusable Components

Examples:

  • Hero

  • Navbar

  • Footer

  • Cards

  • Buttons

Working Flow of SDUI

User Opens App

      ↓

Frontend Requests Screen

      ↓

Backend Sends JSON Config

      ↓

Renderer Parses JSON

      ↓

Frontend Renders Components

Dynamic Rendering

Dynamic rendering means:

UI is generated during runtime using backend configuration.

Example:

Today:

Hero → Features → Footer

Tomorrow:

Hero → Pricing → Testimonials → FAQ

No frontend deployment required.

JSON Schema

JSON schema defines UI structure.

Example:

{

  "type": "button",

  "text": "Login"

}

Frontend understands:

  • which component to render

  • what data to display

Personalization

Different users can see different UI.

Example:

Premium User

{

  "banner": "Premium Movies"

}

New User

{

  "banner": "Start Free Trial"

}

Backend sends UI based on:

  • user type

  • subscription

  • preferences

A/B Testing

A/B testing means showing different UI versions to different users.

Example:

  • User A sees red button

  • User B sees green button

Company checks which version performs better.

SDUI makes experimentation easier.

Action Handling

Backend can also control actions.

Example:

{

  "action": {

    "type": "navigate",

    "screen": "checkout"

  }

}

Frontend handles navigation dynamically.

Animations in SDUI

Frontend already contains animation logic.

Backend only sends configuration.

Example:

{

  "animation": "fade-in"

}

Frontend applies corresponding animation dynamically.

Advantages of SDUI

  • Faster UI updates

  • Dynamic layouts

  • Better personalization

  • Easier A/B testing

  • Reduced deployments

  • Reusable components

  • Cross-platform consistency

Disadvantages of SDUI

  • More complex architecture

  • Harder debugging

  • Backend dependency

  • Rendering overhead

  • Advanced animations can be difficult

Modular Architecture in SDUI

Modern SDUI systems use reusable modular components.

Example:

components/

 ├── hero.json

 ├── footer.json

 ├── pricing.json

Benefits:

  • reusable layouts

  • cleaner architecture

  • better scalability
